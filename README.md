# Cooperative Math — интерактивный генератор

[Открыть демо](https://andreya1998.github.io/cooperative-math-demo/)

Две демонстрации в одной странице: новые варианты **4 286 задач MATH** и деревья связанных подзадач с точными алгоритмическими ответами. Достаточно современного браузера: устанавливать Python или запускать локальный сервер не нужно. При первом открытии загружается браузерный Python; последующие вычисления происходят в Web Worker и не блокируют интерфейс.

## Попробовать

**Одиночная задача.** Выберите раздел, train/test и номер, получите шаблон, затем нажмите «Заполнить числа». Кнопка «Случайная задача» выбирает случайную задачу из текущего раздела и выборки. Случайный выбор также показывает незаполненный шаблон; числа генерируются отдельной кнопкой. «Сбросить» возвращает тот же шаблон. Ответ заполненного варианта виден сразу.

**Дерево задач.** Задайте глубину и ширину основания, нажмите «Новая схема», затем «Заполнить числа». Схема показывает дерево и общий текст с незаполненными внешними параметрами. Вариант заполняет ту же схему: видны ответы всех узлов, преобразованные значения на связях, входы родительских задач и ответ вершины. «Сбросить» возвращает схему с плейсхолдерами. Внешние параметры отмечены синим, входы из ответов подзадач — янтарным.

Сиды выбираются автоматически. Для повторения включите «Задать сид» и введите десятичное число от 0 до 18446744073709551615. У схемы и параметров основания разные сиды. Вкладки сохраняют текущие результаты. Выбор отдельных задач запоминается также при переходах между разделами и train/test. В вершинах и карточках дерева указаны раздел MATH, исходный номер задачи и выборка train/test. Кнопка копирования выдаёт исходное условие для модели, без оформительских вставок.

«Скачать шаблон» сохраняет точный JSON схемы. После заполнения «Скачать задачу» сохраняет JSON с полями `schema` и `variant`: условие, ответ, параметры основания и ход вычислений находятся в `variant.instance`, данные отображения — в `variant.presentation`. Оба исходных JSON-пакета включаются побайтно, без повторной сериализации JavaScript и потери точности больших целых.

Для 3 955 задач видны отдельные символические или вычисляемые места подстановки.
В 331 структурном случае интерфейс честно показывает именованные входы и целое
вычисляемое условие: автоматически восстанавливать недоказанный символьный шаблон
по нескольким примерам было бы ненадёжно. Генерация и точные ответы доступны для
всех 4 286 ID. [Текущий инвентарь отображения](reports/atomic-patterns.json).

## Как устроена композиция

Глубина — число уровней, ширина — число задач основания. Корень всегда один. ДП проверяет достижимость формы и допустимый бюджет внутренних узлов; генератор выбирает продолжения среди осуществимых вариантов. Компактный бюджет ограничивает длинные цепочки одноаргументных задач. Семплирование поддерживает разнообразие доступных шаблонов, но не является равномерным по всем возможным деревьям.

Каждый ответ ребёнка поступает в отдельный вход совместного адаптера родителя. Адаптер преобразует ответы по явно записанным детерминированным правилам в согласованный набор допустимых параметров. Его правила входят в текст и исполняемый солвер. Для каждого листа сертифицирована возможность повлиять на итог; это не означает, что любая замена значения обязательно изменит ответ.

Поддерживаются глубина 1–12 и ширина до 128. Если запрошенную ширину получить нельзя, выбирается максимальная достижимая поддержанная ширина и показывается предупреждение. По умолчанию шаблоны не повторяются; если это невозможно, повторения разрешаются с предупреждением. Исчерпание лимита точного поиска — ошибка, а не доказательство невозможности.

## Архитектура и воспроизводимость

- `index.html` и модули интерфейса: одна страница с общими вкладками и рендерером KaTeX.
- `worker.js`: закреплённый Pyodide 314.0.7 и исходные Python-солверы. Вычисления выполняются в браузере.
- `rpc.js`, `transport.js`: очередь запросов, состояния загрузки и повторная попытка. Схемы передаются исходными JSON-строками, без потери больших целых в JavaScript.
- `python/math_demo/`: независимый от HTTP API и представление математических условий.
- `runtime.zip`, `runtime.json`: воспроизводимый пакет генератора, корпуса и сертифицированных профилей; SHA-256 архива и каждого файла. Источник генератора указан в манифесте.
- `tests/`: проверки API, оформления, передачи точных чисел и реального браузерного выполнения.

Исследовательский репозиторий остаётся источником математической логики. Публичная демонстрация содержит её проверенный экспорт, без внутренних отчётов и истории исследований. У корпуса сохранены исходные ID и train/test: 2 519 и 1 767 задач. ID доступны в технических деталях, но не попадают в текст композитной задачи для модели.

Для точного повторения сохраняйте JSON схемы, сид параметров и версию `runtime.json`. Разные сиды могут давать одинаковые варианты в конечных доменах. Ограничения параметров и независимые математические проверки выполняются в исходном генераторе. Само изменение чисел не гарантирует отсутствие переобучения.

## Разработка и публикация

Пользователю эти команды не нужны. Автоматические проверки выполняются на Linux-сервере в собственном окружении проекта; предпочтителен проверенный Python 3.14. Зависимости из `requirements-test.txt` устанавливаются через общий кэш пакетов. На Mac выполняются редактирование, синхронизация и визуальная проверка.

```bash
PLAYWRIGHT_BROWSERS_PATH="$PWD/.cache/ms-playwright" .venv/bin/python -m playwright install --only-shell chromium
.venv/bin/python -B scripts/check.py
node --test tests/*.test.mjs
.venv/bin/python -B scripts/build_site.py
```

Проверки запускаются на распакованном публичном runtime, без доступа к исследовательскому репозиторию. На Linux те же браузерные сценарии выполняет Playwright с Chromium: проверяются настоящие Pyodide, Worker, KaTeX и состояние интерфейса. Полная команда проверки требует браузер и не допускает тихого пропуска этих тестов. `PLAYWRIGHT_BROWSERS_PATH` можно задать явно; по умолчанию используется `.cache/ms-playwright` внутри проекта. Сборка `dist/` включает только необходимые статические файлы. Для локальной проверки разработчиком можно временно обслуживать эту папку любым статическим HTTP-сервером; открытие через `file://` не поддерживается модульными Worker.

Обновление runtime из исследовательской ветки:

```bash
python3 -B scripts/export_runtime.py /path/to/math_templates
```

Команда выполняется **в публичном репозитории**, после фиксации проверенного исходного коммита. Затем проверяется и фиксируется публичный экспорт. Push в `main` запускает проверки и публикацию GitHub Pages. Источник Pages: **GitHub Actions**, настроен однократно.
